# 채팅 푸시 표시 개선 — 제한 적용 / 운영 활성화 보류

2026-09-14, `release/1.2.4`. **요청 전체 완료 또는 배포 완료가 아니다.**
실기기 검증 및 아래 남은 정합성 작업 전에는 새 표시를 운영에서 켜지 않는다.

## 이번 변경

- 서버 `decorateChatPush`: 기존 FCM envelope에 표시 필드만 선택적으로 추가한다.
  Snack 제목은 방 이름, 본문은 발신자와 메시지; DM 제목은 기존 서버에서
  결정한 상대 이름(익명 포함), 본문은 메시지다. 2개 이상일 때만 간결한
  안 읽음 보조 문구를 만든다. 사진·파일·투표·답장 미리보기를 지원한다.
- APNs 제목/본문/보조 문구와 DM thread를 추가한다. Snack의 기존 thread,
  collapse key, Android tag, 토큰 선택, 소리, 배지, 카운터 쓰기는 유지한다.
  DM의 이미 계산한 방 안 읽음 수를 표시용 반환값으로 읽을 뿐 새 집계는 없다.
- Android 포그라운드는 기본 MessagingStyle을 사용한다. 최대 5개 미리보기,
  최대 32개 방의 메모리 이력이며 실제 읽음 데이터베이스가 아니다.
  디스크, 이미지, 번역 또는 프로필 조회를 기다리지 않는다.
- DM 로컬 알림도 기존 서버와 같은 계정/방 해시 tag + Android id 0을 사용한다.
  iOS 로컬 thread도 같은 키를 사용한다. 새 DM 로컬 ID는 음수 범위를 사용해
  기존 양수 To-do/Snack 슬롯과 분리한다. 해시/UID는 표시 문자열이 아니다.
- 계정/방별 로컬 show/cancel을 직렬화하고 대기 작업은 계정/세대를 재확인한다.
  방별 삭제 때 이력만 지우며 전체 알림 삭제/읽음 쓰기는 하지 않는다.
  계정 전환 때 메모리 이력을 비운다. 다른 계정의 저장된 tag로 취소하지 않는다.
- 표시를 지워도 마지막 관측 이벤트 시각은 유지하여 이미 관측한 최신 메시지보다
  오래된 포그라운드 푸시의 역전을 막는다. **읽음 watermark를 대체하지 않는다.**

## 상태별 실제 구현 범위

| 상태 | 표시 담당 | 이번 구현 | 아직 안 된 부분 |
| --- | --- | --- | --- |
| Android 포그라운드 | Flutter 로컬 알림 | MessagingStyle, 수신한 미리보기 최대 5개, DM 안정적 슬롯 | OS 실제 렌더링/접근성/소리 검증 |
| Android 백그라운드·종료 | 기존 FCM notification 자동 표시 | 짧은 제목·미리보기, 기존 방별 tag | 여러 원문 메시지 펼침, 원격 stale/read 경계 보호 |
| iOS 포그라운드 | Flutter 로컬 알림 | 제목·보조 문구·thread, DM 로컬 슬롯 취소 | 원격 카드와 혼합한 실제 그룹 표시 검증 |
| iOS 백그라운드·종료 | APNs | 제목·보조 문구·DM thread | 여러 원문 메시지 펼침, 읽음 범위별 원격 카드 취소 |

로컬 이력은 앱 재시작/다른 기기에서 읽은 이력을 알지 못하며 완전한 최근 안 읽음
목록이 아니다. Android 자동 renderer에는 Dart MessagingStyle이 적용되지 않는다.
iOS thread는 그룹 식별자이지 remote request ID가 아니므로 같은 thread만으로
기존 APNs 카드를 선택 취소할 수 없다. native service extension/수신 경로는
이번에 추가하지 않았고 data-only로 전환하지도 않았다.

## 실패 안전성 / 보존 범위

서버는 모든 준비를 끝낸 뒤 원래 FCM send를 **한 번만** 호출한다. 준비 오류나
선택 필드 때문에 보수적 3500-byte envelope 예산을 넘으면 원본 envelope를 그대로
반환한다. 토큰 배열을 제외한 JSON을 바이트 단위로 검사하며 한글/중국어 및
ZWJ 이모지·결합문자 단위를 보존해 자른다. 기존 payload 자체의 과대 용량 문제까지
해결하는 것은 아니다.

로컬 style 준비 오류는 post 이전에만 기본 제목/본문으로 전환한다. 플랫폼 post가
실패했다고 두 번째 post를 하지 않는다(성공 후 응답 유실 시 중복 방지).
기존 채널과 OS 잠금화면 설정을 사용하고 visibility를 public으로 강제하지 않는다.
새 프로필 조회로 익명 이름을 해제하지 않는다.

메시지 저장, 읽음 RPC/트리거 쓰기, 배지 계산, 사용자 알림 설정, 토큰 등록/해제,
탭 이동 payload, 일반 서비스 알림과 To-do 예약 알림 코드는 이번에 변경하지 않았다.
일반 FCM 알림은 채팅 이력/큐에 넣지 않는다. To-do는 별도
`PersonalTodoLocalNotificationService`의 기존 예약/취소 경로를 유지한다.

## 별도 정합성 이슈 — 코드상 위험, 운영 재현 미확인

1. **배지 지연 역전**: background handler는 payload의 badge를 직접 적용하고,
   foreground도 미리보기 gate보다 먼저 배지를 적용한다. 메시지 시각은 전체
   unread aggregate의 버전이 아니므로 이를 임의로 배지 watermark로 쓰지 않았다.
   APNs가 직접 적용하는 badge도 Dart gate로 통제할 수 없다.
2. **읽음과 새 원격 수신 경쟁**: 로컬 큐는 FCM/APNs 자동 renderer와 원자적이지 않다.
   기존 읽음 완료 콜백의 cancel에는 확인된 메시지 경계가 전달되지 않는다.
   따라서 읽기 이후 도착한 같은 방의 새 카드를 지우거나 늦은 원격 푸시가
   읽은 알림을 되살리는 문제를 이 수정만으로 해결했다고 볼 수 없다.
   읽음 RPC가 확인한 경계 + 서버 표시 버전 + native의 정확한 request/slot 확인을
   별도 변경으로 연결하고 경쟁 테스트해야 한다. 단말 시각으로 읽음 경계를 만들지 않는다.
3. **재시도/집계와 전송 분리**: Snack은 FCM 직전 push attempt를 선점하며 DM은
   카운터 이벤트 중복 방지 뒤 전송한다. 선점/집계 후 프로세스 종료나 FCM 실패에
   대한 누락 가능성은 표시 변경 이전부터 존재한다. 중복 방지를 무작정 해제하지 않았으며
   서버 전달 복구 상태를 설계하는 별도 변경이 필요하다.
4. **계정 전환 원격 표시**: Dart의 계정 검사만으로 이미 OS에 전달된 자동 원격
   알림을 차단할 수 없다. 기존 토큰 정책을 바꾸지 않았다. 실기기 검증 필수다.
5. Snack 기존 서버 언어별 토큰 분배는 ko/en이다. 그 분배 정책을 변경하지 않았으므로
   순수 표시 helper의 zh 테스트를 모든 중국어 원격 푸시가 번역된 증거로 보지 않는다.

## 실제 검증

- `functions`: `npm run build` 통과.
- `node scripts/test_chat_push_presentation.js` 통과: 제목/본문/언어/메시지 유형,
  익명 이름, 기존 필드·토큰·채널·소리·배지 불변, 오류/용량 fallback, flag 복귀.
- Flutter 관련 29개 고유 테스트 통과: 새 표시/이력/native style 준비 14개,
  기존 방별 정책/일반 식별/읽음 집계 정책/배지 widget 15개.
- 변경 Dart 파일 정적 분석: error/warning 없음. 기존 및 일부 스타일 lint INFO는 있음.
- 실제 FCM/APNs 전송, OS 표시/큰 글씨/잠금화면, 소리·진동 중복, 방 읽기와 원격
  수신 경쟁, 앱 종료·재시작·계정 전환, To-do 08:00 실발송: **미확인**.
  이번에는 emulator에서 실제 Functions 전체 전달 흐름을 재실행하지 않았다.

## 적용 / 복귀

기본값은 양쪽 모두 OFF다. 새 스타일을 켜지 않아도 안정적 DM 슬롯, 로컬 큐,
계정 검사 등의 표시 식별 보완은 남는다. flag는 읽음/카운터를 변경하지 않는다.

1. 현재 작업 트리에 앞선 nickname/search/chat 변경도 있으므로 이번 표시 변경만
   검토한 릴리스로 분리해야 한다. 현재 dirty 트리 전체를 배포하지 않는다.
2. 테스트 프로젝트에만 서버 `CHAT_PUSH_PRESENTATION_V2=true` 환경값을 지정하고
   `onSnackChatMessageCreated`, `onDMMessageCreated` 두 Functions를 적용한다.
   이 변경에 필요한 새 Firestore Rules, 인덱스, 데이터 마이그레이션은 없다.
3. 테스트 앱을 `--dart-define=CHAT_PUSH_PRESENTATION_V2=true`로 빌드한다.
   서버/앱 flag는 서로 독립적이므로 둘 다 설정해야 모든 구현된 스타일이 켜진다.
4. A/B/C 방 동시 수신, 같은 이벤트 재전달/역순 전달, A방 읽는 중 새 메시지,
   각 앱 상태, 계정 전환, 구버전 payload, 익명/미리보기 숨김, 일반 알림과
   To-do 예약을 Android/iOS에서 확인한다. 위 미구현 경로 해결 전 운영 승인은 보류한다.
5. 복귀는 서버 flag를 `false`로 재배포하고 앱도 같은 Dart define을 `false`로
   빌드/배포한다. 런타임 원격 kill switch는 아니므로 이미 설치된 앱의 flag를
   서버에서 바꿀 수는 없다. 데이터·읽음 상태·알림 설정을 삭제/초기화하지 않는다.
   이미 표시된 OS 카드는 자동으로 과거 디자인으로 재작성하지 않는다.

운영 설정 변경 및 배포는 실행하지 않았다.
