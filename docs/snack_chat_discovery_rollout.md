# SnackChat 검색·멘션·오늘 정리 적용 안내

후속 배포: 2026-09-14 검색·문맥·참여자·멘션검증 callable 4개 및 운영본 기준 멘션 Rules만 적용했습니다. 자세한 범위와 미확인 사항은 [후속 기록](snack_chat_todo_followup_20260914.md)을 참고하세요. 아래는 초기 구현 시점의 기록입니다.

기준: `release/1.2.4`, 작업 시작 HEAD `16a0209e`. 기존 변경을 재사용했으며 DM·알림 트리거·미읽음 집계 구조·번역 정책은 변경하지 않았다. 앱 버전은 이번 작업에서 변경하지 않았다.

## 변경 단위

1. **송신 복구**: 기존 업로드/확정 큐 분리, 고정 messageId, 순번, 즉시 말풍선, 계정별 로컬 캐시를 유지했다. 서버 확인에 실패한 전송은 `uncertain`으로 구분한다. 재시도 전 서버 확인을 별도 직렬 큐에서 실행하며, 권한/입력 오류처럼 확정 거절된 경우만 실패로 표시한다. 불확실한 원격 파일을 삭제하지 않는다. 구버전 캐시 해석을 위해 디스크에는 `sending`과 선택적 `deliveryUncertain`으로 저장한다.
2. **원문/첨부 검색**: 방 정보와 상단 검색에서 날짜·발신자·키워드·사진/파일/링크를 조합한다. 서버가 원문을 최대 160개 조회해 최대 25개 결과를 반환한다. 날짜와 문서 ID 커서로 같은 시각의 메시지도 페이지가 겹치지 않는다. 기본 범위는 최근 30일이며 UI에서 변경 가능하다. 일부 조회와 범위 끝을 구분한다. 검색 결과에 읽음 쓰기는 없다.
3. **멘션**: 참여자 선택으로만 UID/이름/UTF-16 범위를 기록한다. IME 값을 고쳐 쓰지 않는다. 범위를 수정하거나 일반 문자열을 붙여넣기/실행 취소한 경우 UID를 추정하지 않는다. 서버가 현재 참여/계정/차단/본문 범위를 검증한 단기 증명을 만들고, 기존 메시지+방 트랜잭션에서 Rules가 이를 확인한다. 새 알림은 생성하지 않는다.
4. **오늘 정리**: 기존 callable에 선택적 `paged`, `categories`, `relatedToMe`와 스냅샷/커서를 추가했다. 기본 120개/원문 40,000자 구간과 양쪽 3개 원문 문맥을 처리한다. 최종 통합은 선택된 근거 원문을 다시 가져와 처리하며 이전 요약문을 입력하지 않는다. 직접 찾기도 같은 페이지 실행기를 사용한다. 공지와 일반 시스템 안내를 구분하고 익명 개인 투표 없이 집계·마감 상태를 입력한다.

## 권한·정합성 경계

- 검색/문맥/멘션/새 정리 경로는 현재 계정, 참여자 여부, 활성 membership, 참여 순번 기간, 양방향 차단, 삭제, 만료를 검사한다. 긴 서버 응답은 권한을 다시 확인한다.
- 원문 보기는 해당 문서와 앞뒤 최대 12개씩 직접 조회한다. 중간 대화를 순차 로딩하지 않으며 결과 화면을 닫지 않고 원문에서 돌아올 수 있다.
- 조회 실패를 빈 결과/사용 가능으로 바꾸지 않는다. 파일을 열기 직전에 원문·권한·만료를 다시 확인한다. 서버 확인이 실패하면 다운로드를 진행하지 않는다.
- 검색 화면은 표시 중인 결과를 30초마다 최대 100개씩 재검증한다. 재검증 실패 시 오래된 결과를 숨긴다. 새 메시지는 새로고침 안내로 알리고, 사용자가 보던 위치를 강제로 옮기지 않는다. 100개 초과 로드 시 순차 재검증이므로 모든 행이 동시에 갱신되지는 않는다.
- 사진 목록은 **기존 계정별 디스크 캐시의 축소 표시만 사용**한다. 캐시에 없는 사진은 자리표시 아이콘이며 명시적으로 열 때 기존 뷰어가 가져온다. 새 서버 썸네일 생성/과거 사진 백필은 구현하지 않았다. 목록 진입만으로 원본을 일괄 다운로드하지 않는다.
- 서버 순번이 없는 과거 원문도 날짜와 입장 기록으로 허용 범위를 검사한다. 요약 근거는 순번이 없어도 messageId로 보존한다.
- 정리 실행은 송신 큐와 분리되며 진행/중단/재개/일부 결과를 제공한다. 계정·방·요청 세대가 달라진 응답은 현재 화면에 반영하지 않는다. 계정 전환 시 결과/원문 화면의 이전 계정 내용을 숨긴다.
- 재개 시 원문 구간을 다시 확인하고 변경되지 않은 구간은 서버 해시 캐시를 재사용한다. 투표 집계/상태, 삭제/내용, 범위/언어/카테고리/개인 조건을 캐시에 반영한다. 로컬 저장은 요청 메타데이터뿐이며 오래된 로컬 요약으로 권한 검사를 건너뛰지 않는다.
- 1~2개 유효 메시지 구간은 AI 대신 원문이라고 명시해 표시한다. 빈 범위·조건 불일치·처리 실패를 구분한다. 정리/검색/원문 화면으로 가린 채팅에서는 새 읽음 스캔을 시작하지 않는다.

## 처리 한도

- 검색: 요청당 원문 160개, 결과 25개. 기간·커서가 변경되면 새 조회. 수정/삭제 재검증은 요청당 100개 이하.
- 정리: 구간당 최대 120개/40,000자와 원문 경계 문맥, 실행당 40구간. 명시적 답장 원문은 최대 24개/8,000자를 추가 확인하며 한도를 넘으면 문맥 제한을 표시한다. 최종 원문 통합은 근거 ID 180개/60,000자 이하(추가 답장 문맥 별도). 한도 초과는 일부 결과로 남기며 전체 완료로 표시하지 않는다.
- 기존 시간당 AI 요청 20회/3초 간격을 유지한다. 많은 대화는 한 번에 완료되지 않을 수 있으며 범위를 좁히거나 한도 회복 후 재개해야 한다. 변경 없는 구간 캐시는 AI 비용을 추가하지 않는다.
- 동일 실행기의 중복 시작은 합친다. 카테고리 정리의 동일 스냅샷/구간 생성은 서버의 70초 lease로 중복 실행을 제한한다. 직접 찾기는 실행기 중복 방지와 기존 서버 요청량 제한을 사용한다. 서로 다른 요청 시각의 작업은 다른 스냅샷이다.
- 스냅샷은 최대 72시간 유지한다. 중단은 진행 중인 서버 AI 호출 자체를 강제 취소하는 것이 아니라 다음 구간 요청을 멈춘다.

## 배포 순서 (이번 작업에서 운영 배포하지 않음)

1. Functions 빌드 및 테스트 후 다음 callable만 우선 배포한다.
   - `querySnackChatMessages`
   - `getSnackChatMessageContext`
   - `getSnackChatMentionCandidates`
   - `validateSnackChatMentions`
   - `summarizeSnackChatUnread`
2. `firestore.rules` 배포: 선택적 `mentions`, `mentionTargetIds` 및 서버 작성 `snack_chats/{room}/mention_intents/{messageId}` 증명 검증. 기존 필드가 없는 구버전 쓰기는 유지한다. 증명 컬렉션의 클라이언트 직접 읽기/쓰기를 허용하지 않는다.
3. `mention_intents.expiresAt` TTL 정책을 설정하면 만료 증명을 정리할 수 있다. **TTL 동작과 무관하게 Rules가 request.time으로 만료를 거절한다.** 실제 운영 TTL 설정은 미확인이다.
4. 테스트 계정/방으로 Android/iOS 구버전과 새 앱을 함께 확인한 후 클라이언트를 단계적으로 배포한다. 썸네일용 Storage Rules·패키지 변경이나 회원/메시지 백필은 없다.

복합 인덱스 파일 변경은 없다. 서버의 범위 쿼리는 `createdAt` 또는 `sequence`와 같은 방향의 문서 ID를 사용하고 발신자/키워드는 한정된 결과에서 서버 필터링한다. 에뮬레이터는 운영 인덱스 상태를 증명하지 않으므로 운영 색인 누락 여부는 테스트 계정 canary에서 확인해야 한다.

## 검증 결과와 남은 확인

- Functions TypeScript 빌드, 정리 기존 순수 헬퍼/스키마 계약 테스트 통과.
- 기존 채팅 에뮬레이터: 동시 고정 ID 전송, 원자 저장, 응답 유실 후 재시도, 같은 시각 페이지, 지연/중복 읽음 이벤트 및 SnackChat 순번/미읽음 회귀 테스트 통과.
- 새 에뮬레이터: 501개 원문 범위/커서, 공지/일반 시스템 분리, 삭제/차단/권한 변경, 직접 문맥 조회, 안 읽은 1개, 읽음 수 불변, 멘션 정상/위조/변조/만료/소유권, 50명 방의 10개 멘션, 대상 이탈 거절, 구버전 쓰기 통과.
- 501개 fixture는 공지 2개와 일반 시스템 안내를 사용한다. **실제 Gemini로 501개 일반 대화의 품질/원거리 정정 병합을 검증한 것은 아니다.** 원문 통합 경로와 요청/근거 유지 테스트다.
- Flutter: IME/수정/붙여넣기/실행 취소, 멘션/구버전 근거 파싱, 중복 실행 합치기, 원문 기반 통합 payload, 중단/재개, 계정 전환·dispose 뒤 응답·실패 상태 테스트 통과. 320px/큰 글씨 2배의 한·영·중 선택 UI와 원문 왕복 결과 유지 테스트 통과.
- **미검증**: 실제 기기 profile 프레임/기기 간 전달 지연, 운영 푸시·배지, 장시간 백그라운드·강제 종료/실제 네트워크 재연결, 실제 Gemini 품질·지연·동시 실행, 운영 App Check/TTL/색인 설정. 이 검증 전 운영 무회귀 또는 성능 목표 달성을 단정하지 않는다.
- 기존 `[SnackChatTiming]`의 queueWait, firestoreWriteStartedAt, transactionStartedAt/attempt, transactionCommittedAt, 수신, localFrame을 이용해 profile 측정을 이어가야 한다. 이번 작업에서 실제 경합 수치를 얻지 못했으므로 방 문서 집계/순번 구조는 분리하지 않았다.

## 비활성화/복귀

클라이언트 빌드의 독립적인 `--dart-define` 플래그(기본 true):

- `SNACK_CHAT_SEND_RECOVERY_V2=false`: 기존 전송 실패 표시 경로. 고정 ID/보관된 패킷은 유지.
- `SNACK_CHAT_DISCOVERY=false`: 새 검색/첨부/직접 문맥 진입 비활성화, 기존 원문 이동 경로 사용.
- `SNACK_CHAT_MENTIONS=false`: 참여자 선택 숨김. 이미 저장된 선택적 멘션 필드는 삭제하지 않음.
- `SNACK_CHAT_PAGED_SUMMARY=false`: 기존 단건 오늘 정리/직접 찾기 호출 경로.

클라이언트 비활성화를 먼저 적용하고 서버/Rules는 선택적 필드 호환 상태로 유지하는 복귀가 안전하다. 새 앱 사용자가 남아 있는데 멘션 Rules나 callable을 먼저 제거하지 말 것. 사용자 데이터·읽음 커서·배지·알림 설정·대기 패킷을 초기화하는 복귀 작업은 없다.
